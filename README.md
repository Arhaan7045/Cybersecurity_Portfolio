# Cybersecurity Portfolio

A hands-on learning and project portfolio documenting practical cybersecurity skills, lab work, investigations, and lessons learned.

The goal is to build strong foundations and demonstrate the ability to investigate security problems, validate evidence, explain impact, and recommend fixes.

## Learning approach

Learning follows two connected tracks:

### Track A — Foundations
- Linux and command-line skills
- Networking and internet fundamentals
- Windows, PowerShell, identity, and Active Directory

### Track B — Applied security
- Web and API security
- Burp Suite and OWASP vulnerability testing
- Authorised reconnaissance and security testing
- SOC alert triage, investigation, and detection

The tracks reinforce each other. Foundations are practised while applied security topics are introduced through authorised labs and realistic scenarios.

## Practical work and evidence

Each learning episode or project should record:

1. **Scenario and objective** — what needs to be investigated and why.
2. **Actions performed** — commands, tools, requests, and steps actually used.
3. **Evidence observed** — genuine output or behaviour, with sensitive details removed.
4. **Interpretation** — what the evidence supports and what it does not prove.
5. **Impact and limitations** — realistic risk, uncertainty, and alternative explanations.
6. **Next action** — remediation, detection, verification, or further investigation.

Projects should include reproducible steps, a clear README, test evidence, limitations, and practical recommendations.

## Portfolio projects

The portfolio will grow as the required skills are learned and practised. Priority projects include:

- Linux log investigation and log analyser
- Network traffic investigation with Wireshark
- SIEM detection lab
- Web and API security assessment
- Cloud misconfiguration investigation
- IOC extraction and security automation
- Integrated attack-to-detection case study

Only publish work that has genuinely been completed and can be explained. Internship or client-related work must be sanitised and must never expose private data, credentials, internal details, or out-of-scope information.

## Safety and responsible testing

- Test only systems you own, deliberately vulnerable training environments, or systems for which you have explicit authorisation and a clearly understood scope.
- Follow the rules of engagement and programme scope.
- Do not access, retain, or publish other people's data.
- Treat scanner alerts as leads that require validation, not as confirmed vulnerabilities.
- Never publish passwords, tokens, personal information, private customer data, or confidential internship material.
- Do not fabricate screenshots, results, experience, or project outcomes.

## Learning standard

The aim is not to collect commands or tick off episodes. It is to understand how systems work, investigate them methodically, interpret evidence accurately, communicate findings clearly, and demonstrate skills through reproducible practical work.
